## 1. FEATURE

An **Admin** uploads a CSV of products from a new React page (`/bulk-import`). The rows are validated and inserted into the `Products` table **in the background**. The browser never sends the file through the API, and the insert never happens inside an HTTP request. A large file can't go through a single API call: request size limits, timeouts and API memory all get in the way. So the browser uploads straight to Azure Blob Storage with a short-lived SAS URL. A Service Bus message then triggers an Azure Function, and the Function streams the CSV and writes it with `SqlBulkCopy`. The UI polls the job status and shows a summary plus the rows that failed and why.

#### `BackEnd/Samagra.Infrastructure/BulkImport/AzureBlobBulkImportStorage.cs`

```csharp
using Azure;
using Azure.Storage.Blobs;
using Azure.Storage.Sas;
using Microsoft.Extensions.Options;
using Samagra.Application.Interfaces;

namespace Samagra.Infrastructure.BulkImport;

public sealed class AzureBlobBulkImportStorage : IBulkImportStorage
{
    private readonly BlobContainerClient _container;
    private volatile bool _containerEnsured;

    public AzureBlobBulkImportStorage(BlobServiceClient blobService, IOptions<BulkImportOptions> options)
        => _container = blobService.GetBlobContainerClient(options.Value.ContainerName);

    public async Task<Uri> GetUploadUrlAsync(string blobName, TimeSpan validFor, CancellationToken ct = default)
    {
        if (!_containerEnsured)
        {
            await _container.CreateIfNotExistsAsync(cancellationToken: ct);
            _containerEnsured = true;
        }

        var blob = _container.GetBlobClient(blobName);
        if (!blob.CanGenerateSasUri)
            throw new InvalidOperationException(
                "ConnectionStrings:BlobStorage must include an account key to generate SAS URLs.");

        // सिर्फ़ इसी एक blob पर create/write — read/list/delete नहीं
        return blob.GenerateSasUri(
            BlobSasPermissions.Create | BlobSasPermissions.Write,
            DateTimeOffset.UtcNow.Add(validFor));
    }

    public async Task<long?> GetSizeAsync(string blobName, CancellationToken ct = default)
    {
        try
        {
            var props = await _container.GetBlobClient(blobName).GetPropertiesAsync(cancellationToken: ct);
            return props.Value.ContentLength;
        }
        catch (RequestFailedException ex) when (ex.Status == 404)
        {
            return null;
        }
    }
}
```

```csharp
using System.Text.Json;
using Azure.Messaging.ServiceBus;
using Samagra.Application.Interfaces;

namespace Samagra.Infrastructure.BulkImport;

public sealed class ServiceBusBulkImportQueue : IBulkImportQueue
{
    private readonly ServiceBusSender _sender;

    public ServiceBusBulkImportQueue(ServiceBusSender sender) => _sender = sender;

    public Task EnqueueAsync(BulkImportMessage message, CancellationToken ct = default)
    {
        var sbMessage = new ServiceBusMessage(JsonSerializer.SerializeToUtf8Bytes(message))
        {
            // queue पर duplicate detection on हो तो एक job दो बार queue नहीं होगा
            MessageId = message.JobId.ToString(),
            ContentType = "application/json",
            Subject = "bulk-import"
        };

        return _sender.SendMessageAsync(sbMessage, ct);
    }
}
```

#### `BackEnd/Samagra.Infrastructure/BulkImport/DependencyInjection.cs`

```csharp
using Azure.Messaging.ServiceBus;
using Azure.Storage.Blobs;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Options;
using Samagra.Application.Interfaces;
using Samagra.Infrastructure.Repositories;

namespace Samagra.Infrastructure.BulkImport;

public static class DependencyInjection
{
    public static IServiceCollection AddBulkImport(this IServiceCollection services, IConfiguration config)
    {
        services.AddOptions<BulkImportOptions>()
            .Bind(config.GetSection(BulkImportOptions.SectionName));

        // Connection strings first use पर check होते हैं, startup पर नहीं —
        // ताकि बिना Azure setup के बाकी API local चलती रहे
        services.AddSingleton(_ => new BlobServiceClient(
            config.GetConnectionString("BlobStorage")
            ?? throw new InvalidOperationException("ConnectionStrings:BlobStorage is not configured.")));

        services.AddSingleton(_ => new ServiceBusClient(
            config.GetConnectionString("ServiceBus")
            ?? throw new InvalidOperationException("ConnectionStrings:ServiceBus is not configured.")));

        services.AddSingleton(sp => sp.GetRequiredService<ServiceBusClient>()
            .CreateSender(sp.GetRequiredService<IOptions<BulkImportOptions>>().Value.QueueName));

        services.AddSingleton<IBulkImportStorage, AzureBlobBulkImportStorage>();
        services.AddSingleton<IBulkImportQueue, ServiceBusBulkImportQueue>();
        services.AddScoped<IBulkImportJobRepository, BulkImportJobRepository>();

        return services;
    }
}
```

#### `BackEnd/Samagra.Infrastructure/Repositories/BulkImportJobRepository.cs`

```csharp
using Microsoft.EntityFrameworkCore;
using Samagra.Application.Interfaces;
using Samagra.Domain.Entities;
using Samagra.Infrastructure.Data;

namespace Samagra.Infrastructure.Repositories;

public sealed class BulkImportJobRepository : IBulkImportJobRepository
{
    private readonly AppDbContext _db;

    public BulkImportJobRepository(AppDbContext db) => _db = db;

    public async Task AddAsync(BulkImportJob job, CancellationToken ct = default)
        => await _db.BulkImportJobs.AddAsync(job, ct);

    // tracked — controller status update करता है
    public async Task<BulkImportJob?> GetByIdAsync(Guid id, CancellationToken ct = default)
        => await _db.BulkImportJobs.FirstOrDefaultAsync(j => j.Id == id, ct);

    public async Task<IReadOnlyList<BulkImportJob>> GetRecentAsync(Guid createdBy, int take, CancellationToken ct = default)
        => await _db.BulkImportJobs
            .AsNoTracking()
            .Where(j => j.CreatedBy == createdBy)
            .OrderByDescending(j => j.CreatedAtUtc)
            .Take(take)
            .ToListAsync(ct);

    public async Task<IReadOnlyList<BulkImportRowError>> GetRowErrorsAsync(Guid jobId, int take, CancellationToken ct = default)
        => await _db.BulkImportRowErrors
            .AsNoTracking()
            .Where(e => e.JobId == jobId)
            .OrderBy(e => e.RowNumber)
            .Take(take)
            .ToListAsync(ct);

    public async Task SaveChangesAsync(CancellationToken ct = default)
        => await _db.SaveChangesAsync(ct);
}
```

```csharp
// Flow: upload-url → browser PUTs file to blob → start → Service Bus → Samagra.Functions
[ApiController]
[Route("api/[controller]")]
[Authorize]
public class BulkImportsController : ControllerBase
{
    private static readonly string[] AllowedExtensions = [".csv"];

    private readonly IBulkImportJobRepository _jobs;
    private readonly IBulkImportStorage _storage;
    private readonly IBulkImportQueue _queue;
    private readonly BulkImportOptions _options;

    public BulkImportsController(
        IBulkImportJobRepository jobs,
        IBulkImportStorage storage,
        IBulkImportQueue queue,
        IOptions<BulkImportOptions> options)
    {
        _jobs = jobs;
        _storage = storage;
        _queue = queue;
        _options = options.Value;
    }

    // POST /api/bulkimports/upload-url
    [HttpPost("upload-url")]
    public async Task<IActionResult> CreateUploadUrl([FromBody] CreateUploadUrlRequest request, CancellationToken ct)
    {
        var userId = GetUserId();
        if (userId is null) return Unauthorized();

        var fileName = Path.GetFileName(request.FileName);
        if (!AllowedExtensions.Contains(Path.GetExtension(fileName), StringComparer.OrdinalIgnoreCase))
            return BadRequest(new { message = "Only .csv files are supported" });

        if (request.FileSizeBytes > _options.MaxFileSizeBytes)
            return BadRequest(new { message = $"File is larger than {_options.MaxFileSizeBytes / (1024 * 1024)} MB" });

        var jobId = Guid.NewGuid();
        // blob name user input से नहीं बनता — सिर्फ़ jobId
        var blobName = $"products/{jobId}.csv";

        var validFor = TimeSpan.FromMinutes(_options.UploadUrlExpiryMinutes);
        var uploadUrl = await _storage.GetUploadUrlAsync(blobName, validFor, ct);

        await _jobs.AddAsync(new BulkImportJob
        {
            Id = jobId,
            FileName = fileName,
            BlobName = blobName,
            Status = BulkImportStatus.Pending,
            CreatedBy = userId.Value
        }, ct);
        await _jobs.SaveChangesAsync(ct);

        return Ok(new CreateUploadUrlResponse(jobId, uploadUrl.ToString(), DateTimeOffset.UtcNow.Add(validFor)));
    }

    // POST /api/bulkimports/{id}/start — browser upload पूरा होने के बाद
    [HttpPost("{id:guid}/start")]
    public async Task<IActionResult> Start(Guid id, CancellationToken ct)
    {
        var job = await GetOwnJobAsync(id, ct);
        if (job is null) return NotFound();

        if (job.Status != BulkImportStatus.Pending)
            return Conflict(new { message = $"Job is already {job.Status}" });

        var size = await _storage.GetSizeAsync(job.BlobName, ct);
        if (size is null)
            return BadRequest(new { message = "File has not been uploaded yet" });
        if (size > _options.MaxFileSizeBytes)
            return BadRequest(new { message = "Uploaded file exceeds the size limit" });

        // पहले Queued save करो, फिर message भेजो — वरना Function को DB में Pending job मिल सकता है
        job.Status = BulkImportStatus.Queued;
        await _jobs.SaveChangesAsync(ct);

        try
        {
            await _queue.EnqueueAsync(new BulkImportMessage(job.Id, job.BlobName), ct);
        }
        catch
        {
            job.Status = BulkImportStatus.Pending;   // user दोबारा start कर सके
            await _jobs.SaveChangesAsync(CancellationToken.None);
            throw;
        }

        return Accepted(ToResponse(job));
    }

    // GET /api/bulkimports/{id} — UI इसे poll करता है
    [HttpGet("{id:guid}")]
    public async Task<IActionResult> GetById(Guid id, CancellationToken ct)
    {
        var job = await GetOwnJobAsync(id, ct);
        return job is null ? NotFound() : Ok(ToResponse(job));
    }

    // GET /api/bulkimports
    [HttpGet]
    public async Task<IActionResult> GetRecent(CancellationToken ct)
    {
        var userId = GetUserId();
        if (userId is null) return Unauthorized();

        var jobs = await _jobs.GetRecentAsync(userId.Value, 20, ct);
        return Ok(jobs.Select(ToResponse));
    }

    // GET /api/bulkimports/{id}/errors
    [HttpGet("{id:guid}/errors")]
    public async Task<IActionResult> GetErrors(Guid id, CancellationToken ct)
    {
        var job = await GetOwnJobAsync(id, ct);
        if (job is null) return NotFound();

        var errors = await _jobs.GetRowErrorsAsync(id, 500, ct);
        return Ok(errors.Select(e => new BulkImportRowErrorResponse(e.RowNumber, e.Message)));
    }

    private async Task<BulkImportJob?> GetOwnJobAsync(Guid id, CancellationToken ct)
    {
        var userId = GetUserId();
        var job = await _jobs.GetByIdAsync(id, ct);
        return job is not null && job.CreatedBy == userId ? job : null;
    }

    private Guid? GetUserId()
    {
        var raw = User.FindFirstValue(ClaimTypes.NameIdentifier) ?? User.FindFirstValue("uid");
        return Guid.TryParse(raw, out var id) ? id : null;
    }

    private static BulkImportJobResponse ToResponse(BulkImportJob j) => new(
        j.Id, j.FileName, j.Status.ToString(), j.TotalRows, j.SucceededRows, j.FailedRows,
        j.ErrorMessage, j.CreatedAtUtc, j.CompletedAtUtc);
}
```

#### `BackEnd/Samagra.Functions/Import/ProductCsvImporter.cs`

```csharp
using System.Data;
using System.Globalization;
using Azure.Storage.Blobs;
using CsvHelper;
using CsvHelper.Configuration;
using Microsoft.Data.SqlClient;
using Microsoft.Extensions.Logging;
using Samagra.Application.Interfaces;
using Samagra.Domain.Entities;

namespace Samagra.Functions.Import;

public sealed class ProductCsvImporter
{
    private const int BatchSize = 5_000;
    private const int MaxStoredErrors = 1_000;

    private readonly ImportSettings _settings;
    private readonly BlobContainerClient _container;
    private readonly ILogger<ProductCsvImporter> _logger;

    public ProductCsvImporter(ImportSettings settings, BlobServiceClient blobService, ILogger<ProductCsvImporter> logger)
    {
        _settings = settings;
        _container = blobService.GetBlobContainerClient(settings.ContainerName);
        _logger = logger;
    }

    public async Task ImportAsync(BulkImportMessage message, CancellationToken ct)
    {
        await using var conn = new SqlConnection(_settings.SqlConnectionString);
        await conn.OpenAsync(ct);

        if (!await TryMarkProcessingAsync(conn, message.JobId, ct))
        {
            _logger.LogInformation("Job {JobId} is missing or already completed — skipping", message.JobId);
            return;
        }

        try
        {
            await RunImportAsync(conn, message, ct);
        }
        catch (InvalidImportFileException ex)
        {
            // retry बेकार है — job fail करो और message complete होने दो
            await MarkFailedAsync(conn, message.JobId, ex.Message);
        }
        catch (Exception ex)
        {
            // transient (SQL/blob) — fail mark करो और rethrow, Service Bus redeliver करेगा
            _logger.LogError(ex, "Bulk import {JobId} failed", message.JobId);
            await MarkFailedAsync(conn, message.JobId, "Processing failed, will retry: " + ex.Message);
            throw;
        }
    }

    private async Task RunImportAsync(SqlConnection conn, BulkImportMessage message, CancellationToken ct)
    {
        var categories = await LoadCategoriesAsync(conn, ct);

        // सारे products + job update एक transaction में — retry पर आधा import duplicate नहीं होगा
        await using var tx = (SqlTransaction)await conn.BeginTransactionAsync(ct);

        if (await IsCompletedLockedAsync(conn, tx, message.JobId, ct))
            return;

        using var bulk = new SqlBulkCopy(conn, SqlBulkCopyOptions.CheckConstraints, tx)
        {
            DestinationTableName = "dbo.Products",
            BulkCopyTimeout = 0
        };
        var products = CreateProductsTable();
        foreach (DataColumn c in products.Columns)
            bulk.ColumnMappings.Add(c.ColumnName, c.ColumnName);

        var errors = new List<(int Row, string Message)>();
        int total = 0, succeeded = 0, failed = 0;

        var blob = _container.GetBlobClient(message.BlobName);
        await using (var stream = await blob.OpenReadAsync(cancellationToken: ct))
        using (var reader = new StreamReader(stream))
        using (var csv = new CsvReader(reader, new CsvConfiguration(CultureInfo.InvariantCulture)
        {
            TrimOptions = TrimOptions.Trim,
            PrepareHeaderForMatch = a => a.Header.Trim().ToLowerInvariant(),
            MissingFieldFound = null,
            BadDataFound = null
        }))
        {
            if (!await csv.ReadAsync() || !csv.ReadHeader())
                throw new InvalidImportFileException("File is empty");

            var headers = csv.HeaderRecord!.Select(h => h.Trim()).ToHashSet(StringComparer.OrdinalIgnoreCase);
            var missing = ProductCsvColumns.Required.Where(r => !headers.Contains(r)).ToList();
            if (missing.Count > 0)
                throw new InvalidImportFileException("Missing columns: " + string.Join(", ", missing));

            while (await csv.ReadAsync())
            {
                ct.ThrowIfCancellationRequested();
                total++;

                var error = TryAddRow(csv, categories, products);
                if (error is null)
                {
                    succeeded++;
                }
                else
                {
                    failed++;
                    if (errors.Count < MaxStoredErrors)
                        errors.Add((csv.Parser.Row, error));
                }

                if (products.Rows.Count >= BatchSize)
                {
                    await bulk.WriteToServerAsync(products, ct);
                    products.Clear();
                }
            }
        }

        if (products.Rows.Count > 0)
            await bulk.WriteToServerAsync(products, ct);

        await WriteErrorsAsync(conn, tx, message.JobId, errors, ct);
        await MarkCompletedAsync(conn, tx, message.JobId, total, succeeded, failed, ct);

        await tx.CommitAsync(ct);

        _logger.LogInformation("Job {JobId}: {Succeeded}/{Total} rows imported, {Failed} failed",
            message.JobId, succeeded, total, failed);
    }

    // Validation error हो तो message लौटाता है, वरना row add करके null
    private static string? TryAddRow(CsvReader csv, Dictionary<string, Guid> categories, DataTable products)
    {
        var name = Field(csv, ProductCsvColumns.Name);
        var description = Field(csv, ProductCsvColumns.Description);
        var priceRaw = Field(csv, ProductCsvColumns.Price);
        var stockRaw = Field(csv, ProductCsvColumns.Stock);
        var categoryName = Field(csv, ProductCsvColumns.CategoryName);
        var imageUrl = Field(csv, ProductCsvColumns.ImageUrl);

        if (string.IsNullOrWhiteSpace(name)) return "Name is required";
        if (name.Length > 200) return "Name is longer than 200 characters";
        if (description?.Length > 2000) return "Description is longer than 2000 characters";

        if (!decimal.TryParse(priceRaw, NumberStyles.Number, CultureInfo.InvariantCulture, out var price) || price < 0)
            return $"Invalid Price '{priceRaw}'";
        if (decimal.Round(price, 2) != price || price > 9_999_999_999_999_999.99m)
            return $"Price '{priceRaw}' must have at most 2 decimals";

        if (!int.TryParse(stockRaw, NumberStyles.Integer, CultureInfo.InvariantCulture, out var stock) || stock < 0)
            return $"Invalid Stock '{stockRaw}'";

        if (string.IsNullOrWhiteSpace(categoryName) || !categories.TryGetValue(categoryName, out var categoryId))
            return $"Unknown category '{categoryName}'";

        // Full URL या site-relative path (/assets/1.webp) — दोनों चलेंगे
        if (!string.IsNullOrWhiteSpace(imageUrl)
            && !Uri.TryCreate(imageUrl, UriKind.Absolute, out _)
            && !imageUrl.StartsWith('/'))
            return $"Invalid ImageUrl '{imageUrl}'";

        products.Rows.Add(
            Guid.NewGuid(),
            name,
            string.IsNullOrWhiteSpace(description) ? DBNull.Value : description,
            price,
            stock,
            true,
            DateTime.UtcNow,
            categoryId,
            string.IsNullOrWhiteSpace(imageUrl) ? DBNull.Value : imageUrl);

        return null;
    }

    private static string? Field(CsvReader csv, string column)
        => csv.TryGetField<string>(column.ToLowerInvariant(), out var value) ? value : null;

    private static DataTable CreateProductsTable()
    {
        var t = new DataTable();
        t.Columns.Add("Id", typeof(Guid));
        t.Columns.Add("Name", typeof(string));
        t.Columns.Add("Description", typeof(string));
        t.Columns.Add("Price", typeof(decimal));
        t.Columns.Add("Stock", typeof(int));
        t.Columns.Add("IsActive", typeof(bool));
        t.Columns.Add("CreatedAt", typeof(DateTime));
        t.Columns.Add("CategoryId", typeof(Guid));
        t.Columns.Add("ImageUrl", typeof(string));
        return t;
    }

    private static async Task WriteErrorsAsync(
        SqlConnection conn, SqlTransaction tx, Guid jobId, List<(int Row, string Message)> errors, CancellationToken ct)
    {
        if (errors.Count == 0) return;

        var t = new DataTable();
        t.Columns.Add("JobId", typeof(Guid));
        t.Columns.Add("RowNumber", typeof(int));
        t.Columns.Add("Message", typeof(string));
        foreach (var (row, msg) in errors)
            t.Rows.Add(jobId, row, msg.Length > 1000 ? msg[..1000] : msg);

        using var bulk = new SqlBulkCopy(conn, SqlBulkCopyOptions.CheckConstraints, tx)
        {
            DestinationTableName = "dbo.BulkImportRowErrors"
        };
        foreach (DataColumn c in t.Columns)
            bulk.ColumnMappings.Add(c.ColumnName, c.ColumnName);

        await bulk.WriteToServerAsync(t, ct);
    }

    private static async Task<Dictionary<string, Guid>> LoadCategoriesAsync(SqlConnection conn, CancellationToken ct)
    {
        var map = new Dictionary<string, Guid>(StringComparer.OrdinalIgnoreCase);
        await using var cmd = new SqlCommand("SELECT Id, Name FROM dbo.Categories WHERE IsActive = 1", conn);
        await using var r = await cmd.ExecuteReaderAsync(ct);
        while (await r.ReadAsync(ct))
            map.TryAdd(r.GetString(1).Trim(), r.GetGuid(0));
        return map;
    }

    private static async Task<bool> TryMarkProcessingAsync(SqlConnection conn, Guid jobId, CancellationToken ct)
    {
        await using var cmd = new SqlCommand("""
            UPDATE dbo.BulkImportJobs
            SET Status = @processing, ErrorMessage = NULL
            WHERE Id = @id AND Status IN (@queued, @processing, @failed)
            """, conn);
        cmd.Parameters.AddWithValue("@id", jobId);
        cmd.Parameters.AddWithValue("@queued", nameof(BulkImportStatus.Queued));
        cmd.Parameters.AddWithValue("@processing", nameof(BulkImportStatus.Processing));
        cmd.Parameters.AddWithValue("@failed", nameof(BulkImportStatus.Failed));
        return await cmd.ExecuteNonQueryAsync(ct) == 1;
    }

    // Row lock — दो deliveries साथ में आएँ तो दूसरी यहाँ wait करेगी और Completed देखकर लौट जाएगी
    private static async Task<bool> IsCompletedLockedAsync(SqlConnection conn, SqlTransaction tx, Guid jobId, CancellationToken ct)
    {
        await using var cmd = new SqlCommand(
            "SELECT Status FROM dbo.BulkImportJobs WITH (UPDLOCK, HOLDLOCK) WHERE Id = @id", conn, tx);
        cmd.Parameters.AddWithValue("@id", jobId);
        var status = (string?)await cmd.ExecuteScalarAsync(ct);
        return status is null || status == nameof(BulkImportStatus.Completed);
    }

    private static async Task MarkCompletedAsync(
        SqlConnection conn, SqlTransaction tx, Guid jobId, int total, int succeeded, int failed, CancellationToken ct)
    {
        await using var cmd = new SqlCommand("""
            UPDATE dbo.BulkImportJobs
            SET Status = @status, TotalRows = @total, SucceededRows = @succeeded, FailedRows = @failed,
                ErrorMessage = NULL, CompletedAtUtc = SYSUTCDATETIME()
            WHERE Id = @id
            """, conn, tx);
        cmd.Parameters.AddWithValue("@id", jobId);
        cmd.Parameters.AddWithValue("@status", nameof(BulkImportStatus.Completed));
        cmd.Parameters.AddWithValue("@total", total);
        cmd.Parameters.AddWithValue("@succeeded", succeeded);
        cmd.Parameters.AddWithValue("@failed", failed);
        await cmd.ExecuteNonQueryAsync(ct);
    }

    private static async Task MarkFailedAsync(SqlConnection conn, Guid jobId, string error)
    {
        await using var cmd = new SqlCommand("""
            UPDATE dbo.BulkImportJobs
            SET Status = @status, ErrorMessage = @error, CompletedAtUtc = SYSUTCDATETIME()
            WHERE Id = @id AND Status <> @completed
            """, conn);
        cmd.Parameters.AddWithValue("@id", jobId);
        cmd.Parameters.AddWithValue("@status", nameof(BulkImportStatus.Failed));
        cmd.Parameters.AddWithValue("@completed", nameof(BulkImportStatus.Completed));
        cmd.Parameters.AddWithValue("@error", error.Length > 2000 ? error[..2000] : error);
        // ct नहीं — cancel होने पर भी status लिखा जाना चाहिए
        await cmd.ExecuteNonQueryAsync();
    }
}
```

```javascript
import axios from 'axios';
import api from '../api/axios';

// Step 1 — backend se job + SAS upload URL lo
export const createUploadUrl = async (file) => {
  const response = await api.post('/bulkimports/upload-url', {
    fileName: file.name,
    fileSizeBytes: file.size,
  });
  return response.data; // { jobId, uploadUrl, expiresAt }
};

// Step 2 — file seedha Blob Storage pe PUT karo (backend se hokar nahi jaati)
// Shared `api` instance nahi — uska baseURL aur cookies blob ke liye galat hain
export const uploadToBlob = async (uploadUrl, file, onProgress) => {
  await axios.put(uploadUrl, file, {
    headers: {
      'x-ms-blob-type': 'BlockBlob',
      'Content-Type': file.type || 'text/csv',
    },
    onUploadProgress: (e) => {
      if (e.total) onProgress?.(Math.round((e.loaded * 100) / e.total));
    },
  });
};

// Step 3 — backend ko batao upload ho gaya, wo Service Bus pe message bhejega
export const startImport = async (jobId) => {
  const response = await api.post(`/bulkimports/${jobId}/start`);
  return response.data;
};

export const getImportJob = async (jobId) => {
  const response = await api.get(`/bulkimports/${jobId}`);
  return response.data;

};
```

```
   ├─ IBulkImportQueue.EnqueueAsync → ServiceBusBulkImportQueue
   │     (JSON BulkImportMessage, MessageId = jobId)   on failure: Status back to Pending, rethrow
   └─ 202 Accepted {job}
   │
   ▼
[Azure Service Bus queue "bulk-imports"]
   │  (peek-lock delivery)
   ▼
[Samagra.Functions: ProcessBulkImportFunction.Run]  [ServiceBusTrigger("%BulkImportQueueName%", Connection="ServiceBus")]
   └─ ProductCsvImporter.ImportAsync(message)
        ├─ open SqlConnection
        ├─ TryMarkProcessingAsync: UPDATE ... SET Status='Processing' WHERE Status IN (Queued, Processing, Failed)
        │     0 rows → job missing or already Completed → log + return (message completes)
        └─ RunImportAsync:
             ├─ LoadCategoriesAsync → Dictionary<name, id> (case-insensitive, IsActive=1)
             ├─ BEGIN TRANSACTION
             ├─ IsCompletedLockedAsync: SELECT Status WITH (UPDLOCK, HOLDLOCK)  → Completed? return (rollback)
             ├─ blob.OpenReadAsync → StreamReader → CsvReader   (streamed, not loaded into memory)
             ├─ header check → missing required columns → InvalidImportFileException
             ├─ per row: TryAddRow (validate) → DataTable row, or (rowNumber, message) error
             ├─ every 5,000 rows: SqlBulkCopy.WriteToServerAsync(table) → dbo.Products; table.Clear()
             ├─ flush remainder
             ├─ WriteErrorsAsync: SqlBulkCopy → dbo.BulkImportRowErrors (max 1,000 stored)
             ├─ MarkCompletedAsync: Status='Completed', TotalRows, SucceededRows, FailedRows, CompletedAtUtc
             └─ COMMIT
        catch InvalidImportFileException → MarkFailedAsync (no rethrow → message completes, no retry)
        catch any other Exception        → MarkFailedAsync + rethrow → Service Bus redelivers
   │
   ▼
[React BulkImportPage] polling: GET /api/bulkimports/{jobId} every 3s (setTimeout in useEffect)
   ├─ until Status ∈ {Completed, Failed}
   ├─ then GET /api/bulkimports (refresh "Recent imports")

   │
[HomePage] GET /api/products/hybrid → HybridCache (30s Redis / 10s memory) → newest products first
```

**Job status lifecycle** (written by two different processes):

| Status | Set by | When |
|---|---|---|
| `Pending` | API (`CreateUploadUrl`) | URL issued; also reset to Pending if the Service Bus send fails |
| `Queued` | API (`Start`) | Blob verified, about to send the message |
| `Processing` | Function (`TryMarkProcessingAsync`) | Message received |
| `Completed` | Function (`MarkCompletedAsync`, inside the transaction) | All rows processed (even if some rows failed) |
| `Failed` | Function (`MarkFailedAsync`) | Bad file, or an exception (an exception is retried, which moves it back to `Processing`) |

## 5. DESIGN DECISIONS

| # | Chose | Why | Alternatives considered / why not |
|---|---|---|---|
| 1 | **Browser uploads directly to Blob via a SAS URL** (the "valet key" pattern) | The file bytes never pass through the API, so API memory, request-size limits and timeouts are not a problem. Blob handles large uploads | *Multipart upload to the API (`IFormFile`)*: the API holds or streams the whole file and ties up a request thread; Kestrel's default body limit is ~30 MB. *API streams to Blob*: still doubles the bandwidth through the API |
| 2 | SAS with **only `Create | Write`**, for **one blob**, **15-minute** expiry, signed with the **account key** | Least privilege: the URL can't read, list or delete anything, and it expires quickly. The account key also works with Azurite locally | *User-delegation SAS (Managed Identity / Entra ID)*: more secure (no account key), but needs Azure AD setup and doesn't work with Azurite. A good production upgrade (see Risks) |
| 3 | Blob name is **`products/{jobId}.csv`**, not the user's filename | A user-controlled filename could overwrite another blob or inject path segments (`../`). The original name is only stored in `BulkImportJobs.FileName` (after `Path.GetFileName`) | Using the user's filename directly |
| 4 | An **explicit `POST /{id}/start`** call after the upload | The API checks the blob exists and its *actual* size, owns the status transition, and decides when to queue | *Event Grid `BlobCreated` → Service Bus*: no extra call, but more infrastructure, and there is no point where the API validates before processing. *Function Blob trigger*: polling-based on Consumption, slower, and it couples processing to blob events with no job record |
| 5 | **Azure Service Bus queue** between the API and the worker | Durable, peek-lock delivery, automatic retries, dead-letter queue, optional duplicate detection; the API and the worker scale independently | *Storage Queue*: cheaper, but no duplicate detection or sessions and a weaker DLQ story. *In-process `BackgroundService` / `Channel`*: the work is lost if the API restarts, and it scales with the API. *Hangfire*: an extra dependency and DB tables |
| 6 | A **separate Azure Function** (isolated worker) does the processing | Runs and scales outside the API; heavy CPU and DB work don't affect API latency | A hosted worker inside the API (same downsides as the `BackgroundService` option in #5) |
| 7 | **`SqlBulkCopy`** in batches of 5,000 | Much faster than row-by-row INSERTs; batching keeps memory bounded | *EF `AddRange` + `SaveChanges`*: change tracking, much slower, high memory. *EFCore.BulkExtensions*: a third-party dependency. *TVP + MERGE*: needed for upserts, but there's no upsert requirement here |
| 8 | **`SqlBulkCopyOptions.CheckConstraints`** | By default, SqlBulkCopy does **not** check FK/CHECK constraints and marks them *untrusted*, which hurts the query plans that rely on them. This keeps `CategoryId` FK checks on | The default options (faster, but leaves constraints untrusted) |
| 9 | **One transaction** for all product inserts + the error rows + the `Completed` update, with the job row locked using `UPDLOCK, HOLDLOCK` | Service Bus delivers **at least once**, so the same message can arrive twice. If the import fails midway, everything rolls back. If a duplicate arrives after success, it sees `Completed` and skips. A concurrent duplicate waits on the lock, then skips. So a file is never half-imported or imported twice | *Commit per batch*: retries would duplicate the earlier batches. *Staging table + a final `INSERT…SELECT`*: also valid and lighter on locks, but more moving parts. *A natural unique key on Products*: no such key exists (`Name` is not unique) |
| 10 | **Invalid rows are skipped and reported**; the job still becomes `Completed` | One bad row shouldn't block 10,000 good ones; the user sees exactly which rows failed (`RowNumber` = the physical CSV line, header = line 1) | *All-or-nothing validation*: stricter, but frustrating for users |
| 11 | A **bad file** (empty, or missing required columns) → `Failed`, **no rethrow** | Retrying can't fix a bad file; retrying would just burn deliveries and end in the dead-letter queue | Rethrow everything (pointless retries) |
| 12 | **Transient errors** (SQL/blob) → `Failed` **+ rethrow** | Service Bus redelivers; `TryMarkProcessingAsync` accepts `Failed` → `Processing`, so the retry proceeds | Swallowing the error (the job would stay `Failed` with no retry) |
| 13 | The Function uses **plain ADO.NET**, not EF / the Infrastructure project | Keeps the Function small and fast to start; `SqlBulkCopy` is ADO.NET anyway. It references only `Samagra.Application` (for `BulkImportMessage` and `BulkImportStatus`) | Referencing Infrastructure + EF: heavier, and pulls Identity etc. into the Function. **Cost:** the status strings in SQL must match the enum names (`nameof(BulkImportStatus.X)` is used to keep them in sync) |
| 14 | **`Status` stored as a string** (`HasConversion<string>()`, max 20) | Readable in SQL, and the Function writes the same strings with plain SQL | Int enum (smaller, but magic numbers in raw SQL) |
| 15 | Azure clients are **resolved lazily** (the factory throws only when first used) | The rest of the API still starts on a dev machine without Blob/Service Bus configured; only the bulk endpoints fail | `ValidateOnStart` (the whole API would refuse to start) |
| 16 | **Polling** every 3s for status | Simple, stateless, works through any proxy | *SignalR / SSE*: push updates, but more infrastructure. The project already uses SSE for the AI chat, so it's an option |
| 17 | Upload uses a **plain `axios.put`**, not the shared `api` instance | The shared instance has `baseURL` = the API and `withCredentials: true`; sending cookies to Blob is wrong and breaks CORS. Plain axios also gives `onUploadProgress` | `fetch` (no upload progress events) |
| 18 | **CsvHelper** for parsing | Handles quoted fields with commas (e.g. `"Noise cancelling, 30h battery"`) and trimming correctly | `string.Split(',')`: breaks on quoted commas |
| 19 | **Admin-only** controller + an **ownership check** (`CreatedBy == current user`) on every job endpoint | Bulk-creating products is an admin action; one admin can't see another admin's jobs | Any authenticated user |
| 20 | Row errors are stored in **their own table**, **capped at 1,000** per job; the API returns at most 500 | Queryable and shown in the UI; the cap stops a 1M-row bad file from creating 1M error rows | Storing errors as text in `ErrorMessage` (not queryable). `FailedRows` still counts **all** failures |
| 21 | `MarkFailedAsync` runs **without** the `CancellationToken` | If the host is shutting down (token cancelled), the Failed status should still be written | Passing `ct` (the status update could be cancelled too) |

## 6. PATTERNS / CONCEPTS USED

**Architecture**
- **Clean Architecture / Ports & Adapters**: `IBulkImportStorage` and `IBulkImportQueue` (ports, in Application) are implemented by Azure adapters in Infrastructure. The API never references the Azure SDKs.
- **Repository pattern**: `IBulkImportJobRepository` → `BulkImportJobRepository` (EF Core). `AsNoTracking()` for reads; `GetByIdAsync` tracks on purpose because the controller then updates `Status`.
- **Valet Key pattern**: the SAS URL gives the client time-limited, scoped, direct access to storage.
- **Queue-Based Load Leveling** + **Asynchronous Request-Reply**: `202 Accepted` + a status endpoint the client polls.
- **Competing Consumers**: several Function instances (and `maxConcurrentCalls: 4`) can read the same queue.
- **Idempotent Consumer**: the transaction + `UPDLOCK, HOLDLOCK` + the "already Completed?" check.
- **Pessimistic locking** (`UPDLOCK, HOLDLOCK`) vs. optimistic concurrency (no `rowversion` is used here).

**.NET**
- **Dependency Injection lifetimes**: `BlobServiceClient`, `ServiceBusClient`, `ServiceBusSender`, the storage and the queue are **singletons** (Azure SDK clients are thread-safe and meant to be reused). The repository is **scoped** (it depends on the scoped `AppDbContext`).
- **Options pattern**: `AddOptions<BulkImportOptions>().Bind(...)`, injected as `IOptions<BulkImportOptions>`.
- **Extension method for DI registration**: `services.AddBulkImport(config)`, the same style as the existing `AddAiServices`.
- **async/await + `CancellationToken`** passed from the action down to EF and the Azure SDKs; `await using` for `SqlConnection`, `SqlTransaction`, the blob stream and the readers.
- **Records** for DTOs and messages (`BulkImportMessage`, `CreateUploadUrlRequest`, …). **Primary constructor** on `InvalidImportFileException`.
- **DataAnnotations + a global action filter** (`ModelValidation`) → automatic 400 on invalid input.
- **EF Core**: Fluent `IEntityTypeConfiguration<T>` picked up by `ApplyConfigurationsFromAssembly`, value conversion (enum → string), composite indexes, cascade delete, migrations.
- **ADO.NET**: `SqlConnection`, `SqlCommand` with parameters (no string concatenation → no SQL injection), `SqlTransaction`, `SqlBulkCopy` + `ColumnMappings`, `DataTable`.
- **Exception filters**: `catch (RequestFailedException ex) when (ex.Status == 404)`.
- **Azure Functions isolated worker**: `FunctionsApplication.CreateBuilder`, `[Function]`, `[ServiceBusTrigger]` with the binding expression `%BulkImportQueueName%` (read from app settings), POCO binding from the message JSON.
- **Raw string literals** (`"""…"""`) for SQL; `nameof(...)` to keep status strings in sync with the enum.
- `volatile bool` flag so `CreateIfNotExistsAsync` runs only on the first upload (harmless if two threads race — it's idempotent).

**React**
- **Hooks**: `useState` (file, step, progress, job, rowErrors, recent, error), `useEffect` (initial load; polling), `useRef` (to reset the uncontrolled `<input type="file">`).
- **Effect cleanup**: `return () => clearTimeout(timer)` stops polling on unmount or when `job` changes.
- **Polling with `setTimeout` chained through state**: each `setJob(next)` re-runs the effect, which schedules the next poll. It stops once the status is final.
- The `react-hooks/set-state-in-effect` lint rule forced the final-status handling into the async callback instead of a second effect.
- **react-router**: `useNavigate` for the Home → Bulk Import button; the new `<Route path="/bulk-import">`.
- **axios** `onUploadProgress` for the progress bar; `Blob` + `URL.createObjectURL` for the client-side "Download CSV template".
- **Tailwind** utility classes, matching the existing pages.

## 7. ERROR HANDLING & EDGE CASES

### Handled

| Case | Where | Behaviour |
|---|---|---|
| Not logged in / not Admin | `[Authorize(Roles = Roles.Admin)]` | 401/403 |
| Another admin's job id | `GetOwnJobAsync` | 404 (doesn't reveal that the job exists) |
| Non-`.csv` file | `CreateUploadUrl` | 400 "Only .csv files are supported" |
| File too large (claimed size) | `CreateUploadUrl` | 400. **Actual** size is re-checked in `Start` (the client could lie) |
| Path tricks in the filename | `Path.GetFileName` + blob name from `jobId` | Neutralised |
| Missing/invalid request body | DataAnnotations + `ModelValidation` filter | 400 with ModelState |
| `Start` before the upload finished | `GetSizeAsync` returns null | 400 "File has not been uploaded yet" |
| `Start` called twice | Status must be `Pending` | 409 Conflict |
| Service Bus send fails | `Start` catch | Status reset to `Pending` (so the user can retry `start`), exception rethrown → 500 |
| Blob/Service Bus not configured | lazy factory | `InvalidOperationException` with a clear message, only on bulk endpoints |
| Account key missing (can't sign a SAS) | `CanGenerateSasUri` check | Clear `InvalidOperationException` |
| Duplicate / redelivered message | `TryMarkProcessingAsync` + locked status check | Skipped; no double import |
| Crash in the middle of the import | Single transaction | Full rollback; the retry starts clean |
| Empty file / missing required columns | `InvalidImportFileException` | Job `Failed` with a message, no retry |
| Header case or spaces (`" price "`) | `PrepareHeaderForMatch` → trim + lowercase | Matched |
| Optional columns missing (`Description`, `ImageUrl`) | `MissingFieldFound = null` | Treated as empty |
| Row validation: empty Name, Name > 200, Description > 2000, Price not a number / negative / >2 decimals / too big for `decimal(18,2)`, Stock not an int / negative, unknown or inactive category, bad ImageUrl (must be absolute or start with `/`) | `TryAddRow` | Row skipped, recorded in `BulkImportRowErrors` |
| Category name case (`electronics` vs `Electronics`) | `StringComparer.OrdinalIgnoreCase` | Matched |
| Very large files | Streaming + 5,000-row batches | Memory stays bounded |
| Status update during shutdown | `MarkFailedAsync` ignores `ct` | Still written |
| Leaving the page while polling | effect cleanup | Timer cleared; no state updates after unmount |

### NOT handled / gaps (be honest with the developer about these)

- **Duplicate products**: uploading the same CSV twice creates every product twice. There is no unique key and no "skip if exists" logic.
- **Polling stops silently after one network error**: in the poll `catch`, `setError(...)` is called but `job` doesn't change, so the effect never re-runs and polling stops. The user has to reload.
- **No resume after a page reload**: the in-progress job lives only in React state. After a reload the user sees it only in "Recent imports", and that list doesn't auto-refresh.
- **Malformed CSV quoting** is silently tolerated (`BadDataFound = null`). A row with broken quotes may be parsed oddly instead of being reported.
- **Abandoned jobs**: if the user gets a URL but never uploads or never calls `start`, the job stays `Pending` forever. Nothing cleans it up.
- **Blobs are never deleted** after processing; storage keeps growing.
- **Messages that fail every retry** go to the Service Bus dead-letter queue (after the queue's max delivery count; the Azure default is 10, and the code doesn't set it). The job then stays `Failed` with "will retry" in its message, and nothing processes the DLQ.
- **Concurrent `Start` calls**: two simultaneous `start` requests can both see `Pending` (no concurrency token on the entity) and both enqueue. The Function's lock still prevents a double import, so the effect is only an extra message.
- **Error rows beyond 1,000** are counted in `FailedRows` but not stored; the UI shows "showing first N".
- **Encoding**: `StreamReader` defaults to UTF-8 (with BOM detection). A file saved in another encoding (e.g. Windows-1252 from old Excel) can garble non-ASCII characters.
- The **"Bulk Import" button is visible to all users**; non-admins get a 403 when they try. The frontend doesn't know the user's role.
- **Product list cache**: new products appear on the home page only after the HybridCache entry expires (up to 30s).

## 9. RISKS / TODO

**Production risks**
1. **`functionTimeout: 00:30:00` in `host.json`**: on the Azure Functions **Consumption** plan the maximum is 10 minutes, so this value is invalid there. It needs a Premium/Flex/Dedicated plan, or a lower value.
2. **One long transaction for the whole file**: a very large import holds locks on `Products` (and the job row) for its whole duration, and bulk inserts can escalate to a table lock. This can block normal product reads and writes. Options: a staging table + a short final `INSERT…SELECT`, or `TABLOCK` during a maintenance window.
3. **Service Bus lock duration**: `maxAutoLockRenewalDuration` is 30 min. Imports longer than that may lose the lock and be redelivered while still running. The DB lock prevents a double insert, but work is wasted.
4. **SAS signed with the account key**: whoever holds the connection string has full control of the storage account. Better: Managed Identity + a **user-delegation SAS**, and Managed Identity for Service Bus and SQL too.
5. **Secrets**: `appsettings.json` currently has a real Azure AI API key and a SQL password (from before this feature). Don't commit it; rotate the key if it was ever pushed.
6. **No malware/content scanning** of uploaded files (Defender for Storage can do this).
7. **CORS on the storage account** must be configured, or uploads fail in the browser with a CORS error.
8. **Status coupling**: the Function writes status strings with raw SQL. Renaming an enum member without updating the data breaks the API's EF mapping.
9. **Migration history oddity (existing before this feature)**: the DB has `20260921174951_AddAiUsage` applied, but there's no file for it in `Migrations/` (the model snapshot does include `AiUsage`). `database update` should apply only `AddBulkImportJobs`, but this is worth knowing.
10. **Transitive vulnerability warning (existing before this feature)**: `System.Security.Cryptography.Pkcs` 9.0.11 comes in through `Microsoft.EntityFrameworkCore.SqlServer` in the other projects. It's pinned to 10.0.13 only in `Samagra.Functions`.

## 10. INTERVIEW — 5 likely questions (with what a good answer covers)

1. **"Why didn't you upload the file through your API?"**
   Request size limits and timeouts, API memory and threads, double bandwidth. The SAS / valet-key pattern: the client talks to storage directly with a scoped, short-lived token. Mention the permissions chosen (Create|Write, one blob, 15 min) and why the blob name comes from the jobId.

2. **"Service Bus is at-least-once. What happens if your function gets the same message twice, or crashes halfway?"**
   One transaction for all inserts + the `Completed` status; `UPDLOCK, HOLDLOCK` on the job row, so a concurrent duplicate waits and then sees `Completed`; a crash rolls everything back and the redelivery starts clean. Bad-file errors are not rethrown (no pointless retries); transient errors are rethrown (retry → DLQ after max deliveries). Also mention the trade-off: one long transaction holds locks (Risk #2).

3. **"Why SqlBulkCopy and not EF Core? Anything to watch out for?"**
   Speed (one bulk stream vs. per-row INSERTs + change tracking), batching for memory. The gotchas: by default it skips constraint checks and marks FKs untrusted, hence `CheckConstraints`; `ColumnMappings` are needed because column order/identity differ; it doesn't fire triggers unless asked; no upsert (that needs a staging table + MERGE).

4. **"Why a queue + Azure Function instead of a BackgroundService in the API?"**
   Durability (survives API restarts), retries + dead-lettering, independent scaling (competing consumers), isolating heavy work from API latency. Trade-offs: more infrastructure, eventual consistency, the client has to poll (202 + status endpoint), and the Consumption plan's timeout limit.

5. **"How does the user know when it's done, and how would you improve that?"**
   The job table holds the status; `202 Accepted` + polling every 3s with `setTimeout` inside `useEffect`, with cleanup. Improvements: SignalR/SSE push (the app already uses SSE for the chat), Service Bus → a notification, fixing the polling-stops-on-error gap, resuming after a reload.

*(Follow-ups an interviewer may also ask: how ownership is enforced (`CreatedBy` check → 404); why `Status` is a string; why the API resolves Azure clients lazily; how you'd secure this with Managed Identity; what Clean Architecture buys here: the API has no Azure SDK reference.)*
